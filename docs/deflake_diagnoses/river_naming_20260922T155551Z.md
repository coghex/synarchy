## Causal chain and corrective direction

1. `tools/river_naming_probe.py:92` queues initialization, calls
   `world.waitForInit(240)`, queues `world.show(page)`, then immediately allows
   `rivers()` to read the implicit active page.
2. `src/Engine/Scripting/Lua/API/World/Lifecycle.hs:192` queues `WorldInit`;
   line 733 queues `WorldShow`. Neither call promises applied completion.
3. `worldWaitForInitFn` at line 798 watches the **active** world and returns
   on its `LoadDone`. During the second initialization, the existing named
   world already satisfies that condition. The probe also ignores the
   returned progress value.
4. `src/World/Thread/Command/Init.hs:142` registers the new page without moving
   the visible selection. `src/World/Thread/Command/UI.hs:31` applies the
   queued show later. Until then, the named page remains the active one.
5. `src/Engine/Scripting/Lua/API/WorldQuery/River.hs:46` obtains parameters
   through `WorldQuery/Lookup.hs`'s active-world lookup, so the immediate query
   correctly returns the still-active named world's rivers.

This is a confirmed fixture synchronization defect, not evidence that the
river naming generator invents a language for custom names. The production
`World.River.Naming` path leaves the name table empty for `Nothing` namer;
the correctly selected runtime query exhibits that behavior.

Repair direction: establish and verify the requested page as the applied
active page before using active-world waits or queries; assert initialization
completion and expected page identity/provenance before grading. Preserve all
12 behavioral checks and fresh-process boundaries. A reusable selection helper
must account for `world.show` being a no-op for a page already in the visible
list; showing an already-visible page does not necessarily promote it to the
head. The trial only needs newly initialized page IDs. Avoid arbitrary sleeps,
relaxing absence checks, or changing the river generator to satisfy a query
against the wrong page.

High confidence follows from matching original failure signatures, directly
observing the wrong active page, the source-level queue/lookup chain, and a
single controlled synchronization intervention passing every unchanged check.
No historical introduction commit was established. This bounded diagnosis is
not a reliability estimate or canonical ten-run committed repair verification.
