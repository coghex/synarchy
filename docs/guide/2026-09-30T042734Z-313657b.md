### [#2699] GUIDE-2. Correct the scenario schema's odd-dimension bounds formula

**Disposition:** amendment to existing [#2699](https://github.com/coghex/synarchy/issues/2699); no new issue.
**Verification:** verified by saved pure arithmetic check.
**Principle:** V-10 and exact rectangular-plane initialization.
**Evidence:** [comment 5823463461](https://github.com/coghex/synarchy/issues/2699#issuecomment-5823463461), “Requirement 7 generalisation,” gives inclusive X `[-ceil(w/2), floor((w-1)/2)]` and Y `[-floor((h-1)/2), ceil(h/2)]` while requiring symmetric odd dimensions. It yields 22×12 cells for 21×11 and 2×2 for 1×1. [#2708](https://github.com/coghex/synarchy/issues/2708) requirement 1 has the consistent formula: `minX=-floor(width/2)`, `maxX=minX+width-1`, `maxY=floor(height/2)`, `minY=maxY-height+1`.
**Consequence:** independently implemented validation and initialization can disagree about legal coordinates or create extra rows/columns.
**Action:** amend #2699 to #2708's formula; pin even, odd, mixed-parity and singleton cases. Preserve selected even-dimension asymmetry. This is a future-spec defect, not a live loader failure. Local evidence: `bounds-check.txt` and saved `bounds-check.patch` in this run's evidence directory.

Follow-up verified unchanged effective specs and the five independent exact-range/count cases below. The owner approved this exact amendment, which was [posted and read back](https://github.com/coghex/synarchy/issues/2699#issuecomment-5904641716). GUIDE-2 is dispositioned as an amendment to existing #2699. The issue remains open; this is not an implementation or canonical readiness verdict. Historical coverage remains the audit snapshot.

**Approved amendment — exact comment posted to #2699:**

> ## Spec amendment: correct exact scenario bounds
>
> Replace only the erroneous formula in “Requirement 7 generalisation” of comment 5823463461 with the rule already specified by #2708 requirement 1:
>
> ```text
> minX = -floor(width / 2)
> maxX = minX + width - 1
> maxY = floor(height / 2)
> minY = maxY - height + 1
> ```
>
> Bounds are inclusive and contain exactly `width × height` tiles. Preserve these independent expected ranges:
>
> - 20×10: X −10…9, Y −4…5.
> - 21×11: X −10…10, Y −5…5.
> - 20×11: X −10…9, Y −5…5.
> - 21×10: X −10…10, Y −4…5.
> - 1×1: only (0,0).
>
> Pin all five cases in `Scenario.Schema`, asserting exact coordinates and tile counts against independent expectations. Use checked arithmetic within the existing dimension domain and document the corrected formula in the same PR's authoring guide.
>
> Retain omitted-dimension expandable behavior, independent camera position, tile clipping, whole-object/footprint rejection, and the separation from the generated world's coordinate convention. All other requirements and review amendments remain in force. This corrects the formula to match the already-selected examples; it introduces no new format decision or runtime scope.
