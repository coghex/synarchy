## Background

Epic #2526, slice EFM-6. #2549 (EFM-5) supplies identity-keyed condition
records for wild and row flora. Groundcover crops are tile-keyed `CropPlot`
values with no instance identity; this issue embeds the same semantic
record in that existing owner and persists it in one implementation PR.
Condition-aware growth, rendering, and harvest refusal belong to #2555
(EFM-7).

Verified against `master` `c3a4cd1331ba` (2026-09-10), before #2549:

- `World.Flora.CropPlot.CropPlotOf s` carries species, planted day, and
  health. `wsCropPlotsRef` owns the canonical tile-keyed map; save capture
  names species into `wpsCropPlots`, and load staging resolves them back.
  The `nameCrop` and `resolveCrop` conversions in `World.Save.Types` change
  only `cpSpecies`. `cropPlotInstance` uses `floraInstanceIdNone` solely as
  a growth adapter.
- `world-activity` is currently v6. Its three-field `CropPlotDTO` uses
  `FloraRef`; the older three-field `CropPlotDTOv1` uses a legacy species
  ordinal. #2549 supplies v7 and its occurrence-condition store before
  this issue moves the component to v8.
- `handleWorldDesignatePlantCommand` inserts a `PlantDesignation`.
  `world.plantCropAt` in `Engine.Scripting.Lua.API.Forage.Crop` performs the
  actual `newCropPlot` insertion on eligible tilled soil without an
  existing plot or flora instance.
- A bare `world.harvestFlora` derives plot eligibility from `floraGrowth`
  and `harvestOpen`; a successful harvest spawns yields and deletes the
  entire plot. Growth-derived dead plots are not harvest-open. These
  functions currently consume no persistent condition record.
- `world.getCropPlotAt` reports growth-derived `id`, `age`, `health`, and
  `phase`; it does not expose a condition.

## Requirements

1. A `CropPlot` carries an optional condition value using the exact shared
   value type from #2549. It contains condition, cause, begin day, render
   context (always `cultivated`), frozen life phase and annual stage, and
   the snapshotted retention outcome. The condition contains no texture
   handle, path, or runtime `FloraId` ordinal. Keep plot ownership
   tile-keyed and page-scoped; never put `floraInstanceIdNone` into the
   identity-keyed store. Newly planted plots start without a condition.
2. Pure operations mark a plot dead with a caller-supplied outcome, clear
   its condition, and read it. Marking an already conditioned plot is
   refused and preserves every original condition field and all other
   plot fields. Clearing removes only the condition; clearing an
   unconditioned plot leaves it unchanged. Reads return the stored value
   or its absence. One page-qualified Haskell query supports both a
   row-flora identity and a canonical plot tile, returning the shared
   record type for #2555 to expose later.
3. The condition follows the plot through capture, encode/decode, species
   reference conversion, and load staging without losing or recomputing
   any field. Deleting the plot, including through an existing successful
   harvest, discards its condition. Replanting on the emptied tile creates
   a fresh unconditioned plot. Planting over an existing plot remains
   refused regardless of its condition. Add no expiry sweep, cleanup
   action, or automatic `await_replanting` transition; EFM-10 owns those.
4. `world-activity` moves from #2549's v7 to v8. Freeze the outgoing v7
   page and crop DTO layouts verbatim, append the optional condition to
   the current crop DTO, and migrate old crops with no condition. Every
   retained decoder must transitively retain its historical crop layout:
   v6 and v7 use the frozen three-field `FloraRef` crop shape; earlier
   retained formats keep their original legacy species representation and
   existing migrations. Freezing a page wrapper must not leave its nested
   crop type pointing at the new four-field DTO. Preserve species
   references, planted day, health, and unrelated page state throughout
   migration. Generate and register a current v8 complete-session fixture
   and baseline through `tools/save_compat_audit.py --generate-session`.
5. Component-boundary validation refuses a crop condition whose expiry
   day precedes its begin day, whose context is not `cultivated`, or whose
   stage or cause is outside the shared vocabulary. Diagnostics name the
   page and canonical tile. Apply the existing persistence rules for
   semantic records and durable species references.
6. Update `docs/persistence_state_inventory.md`'s `wpsCropPlots` and
   `wsCropPlotsRef` rows with the embedded condition and discard-on-delete
   rule. Update the identity section of
   `docs/flora_visual_state_contract.md` to describe plot-value ownership,
   and list the new gates in `docs/engine_contracts.md` section Flora
   visual state and fallback. Required documentation, fixtures, and
   validation evidence belong in this same implementation PR and are
   complete before final review and merge.
7. This slice is persistence-only. Storing a `dead` condition does not yet
   alter growth, freeze the running growth state, change rendering, close
   a harvest window, change planting eligibility, or add Lua fields or
   verbs. An otherwise harvest-open plot carrying a condition remains
   harvestable through the existing path; its successful harvest deletes
   both plot and condition. A plot whose existing growth-derived state is
   dead continues to return `nil` from `world.harvestFlora`. #2555 owns
   integrating conditions into growth and condition-based harvest refusal.
   Wild and row-flora behavior stays as supplied by #2549.

Expected: the build and every named group pass with nonzero example counts.
The new `crop plot condition persistence` group exercises production
operations and persistence paths, covering:

- Mark a planted groundcover plot, capture it, encode/decode it, and stage
  it again. The same page and tile retain every condition field, planted
  day, health, and correctly resolved species reference.
- Read before and after marking; refuse a second mark carrying different
  cause, day, phase/stage, and outcome; prove the original record and
  remaining plot fields are unchanged. Clear and read absence, then clear
  again and prove the plot remains unchanged.
- The uniform Haskell query returns the same record type for a row-flora
  identity and a plot tile without using the reserved non-identity value.
- With Haskell fixture setup supplying a condition, an otherwise
  harvest-open plot still succeeds through the existing Lua harvest verb,
  and its plot and condition disappear. The existing planting verb then
  creates an unconditioned replacement on that tile. Planting over an
  occupied conditioned plot is refused. A growth-derived dead plot still
  refuses harvesting with `nil`.
- Nonempty v6 and v7 crop payloads decode through the real component
  registry into unconditioned current plots while preserving species,
  planted day, and health. Exercise every earlier retained crop-bearing
  layout too. Include unrelated page data, including a v7 occurrence
  condition, to catch field misalignment and accidental state loss. Use
  historical bytes or frozen legacy DTO encoders; an empty map or bytes
  encoded with the new DTO do not prove legacy compatibility.
- Every validation refusal in requirement 5 identifies the page and tile.
