# Map-page storage measurement — issue #2303

This manual experiment supplies evidence for WML-6 and the owner's Q-17
decision. It does not install a codec, cache, quota, or eviction policy.
Results and the owner decision are pending the recorded runs below.

## Reproduce

From the PR checkout, with the production GHC/Cabal toolchain:

```sh
cabal build all
cabal build synarchy-test-headless
python3 tools/test_map_page_codec_measure.py
python3 tools/ci_parity_audit.py
python3 tools/map_page_codec_measure.py --corpus-only
python3 tools/map_page_codec_measure.py --output /tmp/map-codec-first
python3 tools/map_page_codec_measure.py --output /tmp/map-codec-second --compare /tmp/map-codec-first
```

Output paths must be new. Omitting `--output` creates a fresh retained system
temporary directory and prints its location. The expensive command is never
a CI gate. Only the engine-free Python self-test runs in `static-audits` and
the corresponding local gate set.

The Python entry point builds the existing library, then compiles the
tool-only `tools/map_codec/Main.hs` against it through `cabal exec ghc`.
It reuses the headless test harness and its isolated resource root. No new
Cabal component, dependency, runtime CLI mode, or production code is needed.
The build uses the repository's shared build lock, waits in 60-second
intervals, and refuses after 30 minutes of contention.

## Corpus and evidence boundary

`tools/map_codec/corpus.json` is the tracked corpus: seeds, world sizes,
plate counts, levels, and page coordinates. It selects default terrain
pages; analytical modes remain runtime tints, as D-13 requires. Pixels are
regenerated by the unchanged WML-5 `mapPageImage` and `worldGenCellSource`.
No page images are committed.
Untimed world/page generation uses four RTS capabilities; all codec and
memory measurements use one. Generation completes before measurement starts.

The pure self-test checks normalized sizes, addresses, the staggered parity
mapping, unique identities, and category declarations. The real run also
records the actual sampled cells' ocean/lava fluid counts, ice counts and
dry material IDs. Claimed terrain must be present: absent categories are a
fixture failure, not a skip. Transparency is counted in the generated RGBA
image. Latitude and longitude crossings are checked against the sampled
window and real world dimensions; parity is round-tripped through WML-5's
own cell/chunk mapping. Source classifications describe terrain contributing
to a page, including its gutter; they are not percentages of visible pixels.

Every decoded page is exactly 514 × 514 × 4 = **1,056,784 bytes**, in the
generator's row-major RGBA8 order, including the one-texel gutters.

## Codec and timing protocol

The two candidates are raw RGBA8 and RGBA8 PNG through the already-resolved
JuicyPixels library. Both have a separate experimental 32-byte SHA-256
digest. Reported encoded bytes include that digest for both candidates;
payload bytes are also reported separately. This equal integrity allowance
is experimental accounting, not a decision about the later artifact format.

PNG conversion uses the existing storable pixel vector and a materialized
strict ByteString. It does not expand bytes through a Haskell list. Raw
decoding materializes the same RGBA ByteString boundary.

- **Encode:** one unmeasured warmup and five measured encodes in one process;
  report all samples and their median. Input reading and copying, digest
  creation, and output writing are outside this timer. Raw encoding is the
  identity operation; its negligible encode cost excludes I/O and hashing.
- **Isolated decode:** three independent fresh processes per candidate/page,
  each loading exactly one encoded page and its digest before the timer,
  then verifying SHA-256 and fully materializing RGBA inside the timer.
  No decode warmup runs in these processes. Report all samples and median.
- **Bulk decode:** a separate process preloads the complete corpus, then
  decodes it three times. The single reported interval includes SHA-256,
  RGBA materialization, and the loop's input copies. This is warm-process
  corpus throughput, never presented as isolated single-page latency.
- **Clock:** `GHC.Clock.getMonotonicTimeNSec`; one RTS capability (`-N1`).
  The bridge is compiled at `-O2` with CSE and full laziness disabled so
  repeated work cannot collapse into a shared evaluated result.
- **Filesystem:** input file reads and all output writes are outside codec
  timers. No OS page-cache purge is attempted; this is a memory-input codec
  comparison, not an SSD or cold-file-read benchmark. World generation,
  bridge compilation, process startup and JSON reporting are also excluded.

These boundaries measure the codec stage a future cache would use; they do
not measure complete frame latency, disk I/O, or renderer upload latency.

## Memory protocol

Each isolated decode process has its own `wait4` peak resident-set sample.
macOS reports bytes; Linux reports KiB, converted to bytes. This measures
the whole process, including native codec allocations, not just GHC heap
objects. The exact decoded payload size above remains a separate quantity.

Three matching fresh baseline processes per candidate/page read the encoded
input and digest, then exit without decoding. The report retains all
baseline and decode samples, their separate medians, and the nonnegative
difference of those medians. The difference is a derived estimate of
incremental peak process footprint, not an allocation count or an exact
measure of decoder-only memory. Executable mapping, allocator behavior and
OS sampling can make it noisy; memory samples may vary across repeats.

## Determinism and corruption

All five in-process encoded results must be directly byte-equal. A second
fresh encode process must also produce directly equal bytes. The second
full run regenerates world parameters/pages and compares RGBA, encoded
payload, and digest files directly with the first full run. SHA-256 strings
and byte lengths are retained as evidence, but do not replace comparisons.
Timing and peak-memory samples are allowed to vary.

For each encoded page, three independent corruption cases flip exactly one
bit (`xor 1`) in one byte: offset 0, floor(payload length / 2), and the final
payload byte. All offsets are deterministic and in range; original digest
bytes remain intact. Each case reports separately:

1. The external SHA-256 check's outcome.
2. The codec's native decode outcome with the external check bypassed.
3. When native decoding succeeds, exact differing RGBA-byte and pixel counts.

A rejected decode has no output image, so damage is **not applicable**,
never zero. Raw bytes have no native checksum or corruption detector beyond
the exact-length guard. PNG's native behavior is observed rather than
assumed. A failed determinism or integrity check remains in the results and
makes the command fail; it does not remove that candidate from the table.

## Synthetic fine-cache model

The Python trace geometry is checked against the real WML-5 inventories at
world sizes 64, 136, 1024 and 8192 before use. Main traces use size 8192,
levels 0–2, which are all finer than the mandatory-coarse cutoff. Mandatory
coarse/root artifacts are outside this optional fine-cache quota.

The model covers three declared patterns, all reproducible in
`map_page_codec_model.camera_trace`:

- **Home and expeditions:** eight outward-and-back routes of 40 camera
  positions, with home revisits and changes among three zoom levels.
- **Frontier:** 240 camera positions advancing into new territory, changing
  level every 80 positions.
- **Distant inspection:** 120 distant positions, then the same visits in
  reverse order, cycling three levels.

Each position requests an assumed 8 × 5-page 4K viewport plus a one-page
ring (10 × 7), in row-major order, wrapping longitude and clipping latitude.
This is a synthetic request conversion, not a measured renderer footprint
or observed player telemetry. Home-and-expeditions is the provisional main
case; the others test sensitivity.

Each cache starts empty and applies byte-bounded LRU. Every page request,
including repeated requests within overlapping views, counts once in the
hit-rate denominator. A hit moves the page to most-recently-used. Misses
evict least-recently-used pages until the new page fits; an individually
oversized page bypasses storage. Peak resident bytes can never exceed quota.
“Distinct working set” means the sum of bytes of all distinct pages requested
anywhere in that trace, not the largest simultaneous viewport.

Quotas of 16, 64, 256 and 1024 MiB are explored. An explicit **assumed** 5%
partition is reserved for one small auxiliary world and 95% for the main
world. The auxiliary trace sweeps all 45 finest pages of size 136 six times;
level 0 is finer than that world's mandatory-coarse cutoff. Both partitions
and the request-weighted combined hit rate are reported. This assumption
preserves the existing small-auxiliary-world capability; it is not a shipping
partition or a claim to support many full-sized worlds.

Trace pages not in the measured corpus are priced, separately per codec,
at the median measured encoded-page size. Every result is repeated using
the maximum measured size as a sensitivity case. These are explicitly
assumed extrapolations, not measured sizes of the large world's unseen pages.
The corpus maximum is not a proven worst-case size for every generated page.
